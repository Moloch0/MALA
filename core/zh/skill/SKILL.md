# 问题构造

## 定义

一个好问题，是指在给定目标之下，用最少但充分的结构，把真正的未知暴露为一个可以被判定、推进和更新的缺口。

这个定义有四个条件：

- `Judgeable`：必须清楚什么算回答了这个问题，什么不算。
- `Actionable`：不同答案必须导向不同的下一步；否则它就只是一个话题。
- `Updatable`：一旦有新证据进入，问题和答案都可以被修订。
- `Least but sufficient`：相对于给定目标，它既不保留无关的冗余，也不删去关键结构。

这个 skill 只有一个任务：修复原始输入，直到它满足这四个条件。

## 要素

一个问题由以下要素构成：

- `Target`：这个问题最终服务于什么。
- `Object`：这个问题作用于哪个对象、系统、过程、理论或情境。
- `Unknown`：真正缺失的是什么。
- `Criterion`：什么算回答了它，什么算更好或更差。
- `Constraint`：时间、资源、风险、可观测性或适用范围之类的限制。
- `Action`：允许通过哪些动作推进它，例如比较、测试、推理、实验、设计或决策。
- `Evidence`：什么信息会改变当前判断。
- `Boundary`：什么属于这个问题，什么不属于。

如果这些要素还没有形成结构，那么这个输入还不是一个好问题。

## 失效模式

相对于一个好问题，坏问题只有三种基本失效模式：

- `Missing`：某个必要要素缺失了。
- `Mixed`：多个要素或多个问题被揉在了一起。
- `Mismatched`：这个要素存在，但给错了，例如把代理指标当成目标，把态度当成判准，或把相关性当成证据。

做诊断时，不要先发明类别；先检查这三种失效。

所谓冗余并不是第四种失效模式。它要么来自边界没有澄清而导致的混杂，要么来自错误保留无关内容而导致的错配。

## 工作流程

### 1. 提取要素

先从原始输入中提取：

- target
- object
- unknown
- criterion
- constraint
- action
- evidence
- boundary

如果某一项没有给出，就明确标记为缺失。不要偷偷自己补上。

### 2. 诊断失效

对每个要素，检查三件事：

- 它是否缺失
- 它是否和其他要素混在一起
- 它是否错配

诊断应当落在要素本身，而不是停留在模糊的整体评价上。

### 3. 修复

修复只做以下三类工作：

- 补全缺失要素
- 分离混杂要素
- 纠正错配要素

常见修复包括：

- 澄清真正的目标，而不是沿用最顺手的代理指标
- 把一个话题压缩成真正的未知，而不是保留一个宽泛的愿望
- 澄清判准，而不是停留在态度表达的层面
- 补上必要约束，使一个答案能够改变下一步行动
- 指定允许的推进动作，而不是只留下空泛表述
- 说明什么证据会更新当前判断
- 画出边界，把几个混在一起的问题分开

修复的目标不是把措辞写得更漂亮，而是把结构补完整。

### 4. 验证结果

修复之后，只检查四件事：

1. 现在它是否 `Judgeable`？
2. 现在它是否 `Actionable`？
3. 现在它是否 `Updatable`？
4. 现在它是否 `Least but sufficient`？

四项里哪怕还有一项失败，修复都还没有完成。

## 输出

默认按以下顺序输出：

```markdown
原始输入中的问题
- 缺了什么
- 混了什么
- 错了什么

修复后的问题
> ...

最终答案
- ...

修复说明
- 添加了什么
- 分开了什么
- 纠正了什么
```

如果原始输入还没有形成一个问题，先明确指出它仍然只是一个主题、愿望、态度或尚未成形的目标，而不是一个可以直接回答的问题。最终答案应当回应修复后的问题，而不是原始输入。
