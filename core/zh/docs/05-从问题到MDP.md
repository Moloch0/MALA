# 从问题到 MDP

一旦我们承认“提问是在组织搜索”，下一步几乎是被逼出来的：什么样的搜索结构，才算真正可递归求解？

这时引入 MDP，不是因为它听起来更技术，也不是因为想给前面的讨论强行套一个机器学习外壳，而是因为 MDP 恰好提供了一种非常清楚的形式：如果一个问题能被稳定地展开、比较、回退和优化，那么它通常就已经接近某种决策过程。它不一定原封不动就是标准教材里的 MDP，但它至少会要求几个同样的骨架。

这些骨架并不神秘。

首先，你必须知道当前处于什么状态。这里的“状态”不是世界的全部细节，而是对当前局面的某种表示。其次，你必须知道有哪些动作可选，也就是接下来能做什么。再次，你要知道采取某个动作之后，局面会如何变化。然后，你还要有一个评价标准，也就是什么样的结果更好，什么样的结果更差。最后，你还需要某种结束条件，或者至少知道这个过程应该在什么尺度上被评价。

把这些放在一起，就得到了 MDP 的基本轮廓：状态空间、动作空间、转移结构、奖励函数，以及终止条件或折扣结构。

这里最重要的一点是：这些不是技术细节，而是问题之所以能被递归处理的前提。很多人以为问题已经在那里，只是我们后来用某种算法去解它。其实并不是。很多时候，所谓“把问题表述清楚”，本身就是在做这些定义：什么算同一个局面，什么算一次可行操作，什么变化值得追踪，什么结果算作改进。

于是，提问就可以被更精确地翻译出来。提问并不只是说“我想知道什么”，而是在逐步规定：

- 当前局面应当怎样被表示；
- 哪些选择是真正可行动的；
- 行动之后应当追踪哪些后果；
- 什么才算一个更好的未来；
- 这个过程应当在多长的时间尺度上评价。

这一步一旦完成，我们和“回答”的关系也会重新变得清楚。在这个框架里，回答更像什么？更像是一个值。它可能是“当前状态值不值得继续”，也可能是“在这个状态做这个动作值不值得”，或者是“在所有选择里哪一个更优先”。换句话说，回答更像价值估计、更像局部评估、更像在一个已经存在的问题结构中做 value backup。

提问则不同。提问不只是求值，它更像在定义状态表示、目标函数和搜索空间本身。也因此，提问比回答更基础，不是因为它更抽象，而是因为 value 再精确，也只能在既定问题中精确。问题设定一旦错了，后面的优化越充分，错得反而越稳定。

这一点可以用一个很简单的例子说明。假设你问的是“怎样才能学得更好”，但你实际上把奖励函数偷偷改写成了“怎样才能更快获得完成感”，那么后续一切优化都可能导向低质量重复、表面进度和错误自信，而不是更深的理解。算法本身没有犯错，它只是非常认真地解了一个被设错的问题。

同样的事情在更大的系统里会更明显。如果一个平台把“停留时间”当成主要奖励，它优化出来的未必是真正有价值的信息分发，而可能是高刺激、强反馈、低摩擦的内容循环。这里出问题的不是回答，而是问题设定本身。状态怎么切，奖励怎么定，动作空间如何定义，决定了系统究竟在学什么。

这就是为什么，我们最终必须把“什么叫一个好问题”收敛为“什么叫一个好的状态抽象”。因为完整历史通常太大、太乱，也无法直接用于递归决策。真正关键的是：在不丢掉任务相关信息的前提下，我们怎样把历史压缩成一个足以支持后续判断的状态。

于是，前面的认识论命题在这里被压缩成一句更硬的话：

> 好问题等价于好的状态表示。

这句话的含义是，所谓“把问题问对”，不再只是修辞上的准确，而是在数学和算法意义上切出了一个合适的状态空间。它既不能太粗，以至于把真正关键的差异全抹掉；也不能太细，以至于把无关冗余全都背在身上。它必须恰好保留那些会影响未来决策的信息，并删去那些不会影响求解的细节。

当然，这里还有一个边界必须承认：MDP 不会凭空替你定义目标。什么叫“更好”，终究要来自问题本身的规范性输入。换句话说，不存在完全脱离目标的终极问题生成器。一旦目标给定，后面的结构标准就可以越来越严格；但如果目标本身模糊不清，那么再精致的状态抽象也无从谈起。

所以，从问题到 MDP 的真正转折，不是把思想强行技术化，而是把一个更深的事实说清楚：一个问题之所以能被解，不只是因为它有答案，而是因为它先被写成了某种可递归优化的结构。

如果这一点成立，那么下一步的问题就不再是泛泛地谈“好问题”，而是要正式问：一个好的状态抽象，究竟应当满足什么条件？
