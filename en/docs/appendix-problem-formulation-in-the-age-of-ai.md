# Problem Formulation In The Age Of AI

If we place the whole series back into today's technical environment, one direct practical meaning appears: as the cost of generating answers falls rapidly, what becomes truly scarce is no longer the ability to answer, but the ability to formulate problems.

This is not an exaggeration. Large models have already made many forms of cognitive output that used to be expensive become cheap: summaries, rewrites, explanations, translations, induction, analogy, and even quite respectable preliminary argument can now be produced quickly. In other words, answers as compressed results are increasingly being automated at scale.

If we remain inside older habits, an illusion follows naturally: because systems become better at answering, they must also become better at thinking. But the entire chain of argument above has already told us that these are not the same thing. Answers are more like value, local estimation, or compressed result caches. Questioning and problem construction are more like state abstraction, reward specification, and problem formulation. The former evaluate within a given structure; the latter define the structure itself.

This distinction only becomes more important in the age of AI.

Once answers become cheap, the marginal value of answers themselves falls. It is no longer remarkable that a system can quickly produce a paragraph that sounds complete. What is remarkable is whether it can recognize that the question was asked badly, discover that the objective function has been tilted, point out which variables in the state representation are only local correlation and which belong to stable mechanism, and recut a mixed demand into solvable subproblems.

In other words, the more valuable future ability is not to output answers faster, but to discover earlier: what problem are we actually solving?

This is especially clear in the reinforcement-learning analogy. Value computation can become stronger and policy optimization can become faster, but if the state abstraction is wrong, the reward function is wrong, or the action space is incomplete, the system only solves the wrong problem more efficiently. The better it optimizes, the more stably wrong it becomes. Technical progress does not automatically repair problem specification. It magnifies the quality of the specification itself.

That is why problem-formulation ability is becoming a core capability. At minimum it includes the ability to:

- judge what is worth formal solving;
- point out how many different levels of problem are mixed inside the current question;
- clarify what the real target is rather than inheriting the most convenient proxy metric;
- identify which variables are only surface correlation and which are closer to the stable structure of the task;
- know how to compress degrees of freedom in front of a complex object rather than merely adding information.

These abilities were always important, of course, but when answers were scarce they were easily hidden behind "people who can produce answers." Now the situation has changed. If more and more systems can generate a sufficiently fluent answer, then what truly separates people or systems will not be the answer itself, but whether the problem was cut at the right level.

This also gives a less empty answer to the question "what should humans do?" Humans may no longer need to outperform machines in every local answer, but humans still need to take responsibility for higher-level tasks: deciding what counts as the goal, what counts as the constraint, what counts as the problem, what is only noise, what should be preserved, and what should be compressed away. In other words, human advantage will increasingly concentrate in formulating, reframing, and auditing problems rather than simply answering them.

If we want to say it more sharply, we can put it like this:

> In an age flooded with answers, what determines the boundary of understanding is no longer output capacity, but problem-formulation capacity.

This is not a gentle compliment to the idea that "asking matters." It is an increasingly realistic judgment about division of labor. Whoever controls problem formulation determines, at a higher level, the ceiling of all later answers. Whoever can only consume pre-given problems and optimize pre-given objectives can only perform local optimization inside an already fixed coordinate system.

So what is truly worth competing for in the era of large models is not "who can produce more answers," but "who can notice earlier that the present problem has not yet been written correctly." That is the practical landing point of the whole discussion above.
