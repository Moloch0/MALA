# Four Knowledge States and the Problem Paradigm

The main essays have already established a basic claim: answers produce results inside an already specified problem space, while questioning constructs the solvable structure of the problem itself.

That claim can be compressed further into a more practical frame: when a person faces some matter, they may be in at least four different knowledge states. Unless these states are distinguished, "starting from the answer" and "starting from the problem" are too easily blurred together.

## Four Knowledge States

For the same matter, a person may be in at least the following four states:

1. `Knowing what one knows`
2. `Not knowing what one knows`
3. `Knowing what one does not know`
4. `Not knowing what one does not know`

These are not just playful psychological categories. They are an epistemic tool for judging whether the present task mainly requires an answer, or first requires the reconstruction of the problem itself.

## I. Knowing What One Knows

This is the most stable state. The subject not only possesses some knowledge, but knows that they possess it.

A skilled worker knows how to judge whether a material meets standard. A researcher knows which definitions, theorems, or experimental results are already mastered. A person may also clearly know that what they really want is stability rather than nominal upward mobility.

In this state, the task is usually not to reconstruct the problem again, but to retrieve, organize, or state what is already known.

So if a task mainly falls in this state, starting from the answer is usually unproblematic. What is needed here is expression, retrieval, reasoning, or explanation, not a new act of problem construction.

## II. Not Knowing What One Knows

This state is easier to miss. The subject already possesses some usable knowledge, experience, criterion, or intuition, but it has not yet been made explicit, so it cannot stably enter judgment.

Suppose someone says, "I want to change jobs, but I can never decide." They may in fact already know many things: what kind of organizational structure quickly drains them, what tempo they cannot sustain, what kind of growth opportunity is only nominal compensation. The knowledge is not absent. It simply has not yet been organized into a form that can be stated, tested, or compared.

What is missing here is not an externally supplied answer, but the transformation of implicit knowledge into explicit structure.

If one rushes to start from the answer in this state, a system will often jump straight to advice: switch jobs, do not switch, list pros and cons, do more research, ask senior people. Such advice is not necessarily false, but it skips an earlier task: what does the person already know?

This is where the strength of the problem paradigm begins to appear. What is required is not a faster answer, but a prior clarification of the already-known.

## III. Knowing What One Does Not Know

This is the state most like a standard problem. The subject clearly knows where the gap is, and knows what kind of information would fill it.

"How much time do contestants get for a regular Jeopardy clue?"

"What result did this model get on a particular benchmark?"

Once such a problem is formed, the answer paradigm works well, because the problem space has already been mostly fixed. The main task is then to search, reason, calculate, or compare within it.

So if a task clearly falls in this state, starting from the answer is natural. It does not require an additional formulation pass.

## IV. Not Knowing What One Does Not Know

This is the most difficult and also the most fundamental state. The subject lacks not only the answer, but even a correct exposure of the unknown itself.

Take the question, "Why do I always fail to learn this?" It looks like a question, but it may be mixing together ability, task type, time allocation, feedback quality, goal definition, and evaluation standard. The real difficulty is not the absence of a ready-made answer, but that even the missing thing has not yet been cut out.

If one starts directly from the answer here, a system will often silently decide what the problem really is. It may interpret the issue as weak discipline, or bad method, or the wrong task choice. The answer may sound smooth, but smoothness does not mean it has actually hit the problem.

This is why the fourth state is the zone where problem construction is most necessary. What is first required is not an answer, but the first exposure of the unknown out of the surrounding confusion.

## Where the Answer Paradigm Reaches Its Limit

We can now see more clearly that starting from the answer is not wrong, but conditional.

Its condition is that the problem space has already been given. In other words, we already know:

- what exactly is being asked;
- what is genuinely missing;
- what counts as having answered it;
- which conditions are relevant;
- where the boundary is drawn.

Once these have already been established, the answer paradigm is of course effective. The problem is that such establishment is not always automatically available.

The answer paradigm is usually sufficient in the first and third states:

- in the first state, the knowledge is already possessed and only needs to be retrieved or stated;
- in the third state, the unknown has already been exposed and only needs to be filled.

But once we enter the second and fourth states, the answer paradigm begins to distort:

- in the second state, it misses knowledge the subject already has but has not yet made explicit;
- in the fourth state, it pre-decides the target, criterion, and boundary on the subject's behalf.

As a result, what looks like a smooth answer is often only an answer to an undeclared problem.

## Why the Problem Paradigm Covers More

To start from the problem is not simply to "ask first and answer later." It is to acknowledge a fact: in many cases, what first needs work is not the answer, but the conditions under which the problem itself becomes a problem.

It must do at least the following:

- judge which knowledge state the subject is currently in;
- expose the real unknown rather than inherit the surface question;
- reorganize implicit knowledge, mixed targets, wrong criteria, and missing constraints;
- compress a topic, wish, or confusion into a question that can be judged, advanced, and updated.

Therefore the problem paradigm covers more not because it is stronger at every local task, but because it can also handle states that the answer paradigm cannot handle well, especially the second and fourth.

More precisely:

- the answer paradigm handles `what to do after the problem has already been formed`
- the problem paradigm handles `whether the problem has been formed at all, and how it should be formed`

The former solves within a space. The latter constructs the space itself. The former is often more efficient locally; the latter is more comprehensive in scope.

## This Does Not Mean One Should Always Rewrite the Problem

A limit must be added here as well.

To say that starting from the problem is more comprehensive does not mean that one should always begin with problem construction. If a request already clearly belongs to the first or third state, forcing an additional reformulation step will often slow the work down and may even muddy what was originally clear.

So the more rigorous claim is not that problem always stands above answer, but rather:

> When the problem space has already been established, answering is appropriate; when the problem space has not yet been established, or when we are unsure whether it has been established, problem construction is the more basic task.

That is why a good system should not be attached to one fixed posture. It should be able to answer already-formed problems, while also recognizing which inputs have not yet become problems.

## The Point of This Appendix

Placed back into the wider set of essays, these four states help make one thing clearer: why a problem-centered approach is not just a rhetorical preference, but a more comprehensive epistemic strategy.

It is not meant to deny answers, but to limit the range within which answers are actually appropriate. It reminds us that many failures do not come from too few answers, but from a problem that was never written correctly in the first place.

And it is exactly in this sense that problem construction becomes central to the later discussion: what a good problem is made of, how problems fail, and how they can be repaired. Only after this work is done does an answer become meaningful for the first time.
