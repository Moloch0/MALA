# MALA-Graph：形式化草案与理论边界

本文是 MALA-Graph 的**重写版理论草案**。  
它的目的不是把一切都证明完，而是给出一个比旧版更完善的形式化版本，同时明确哪些部分是：

- 可直接接受的前提
- 本文引入的建模定义
- 仍待证明的命题

本文只建立一个**最小而正面的理论框架**：说明如果 MALA-Graph 要成立，它应当被理解成什么，不应当被理解成什么，以及它至少需要哪些形式对象。

本文只依赖以下材料：

- [MALA-core 中文 Skill](../core/zh/skill/SKILL.md)
- [00-skill-hard为什么失败](../core/zh/asset/doc/从skill到控制流/00-skill-hard为什么失败.md)
- [01-skill 与控制流的分层原则](../core/zh/asset/doc/从skill到控制流/01-skill%20与控制流的分层原则.md)
- [02-为什么解释状态难以控制流化](../core/zh/asset/doc/从skill到控制流/02-为什么解释状态难以控制流化.md)

## 1. 出发点

MALA-core 给出的不是一个流程机，而是一个关于“好问题”的结构定义。

一个好问题至少有八要素：

```text
目标、对象、未知、判准、约束、动作、证据、边界
```

并满足四个条件：

```text
Judgeable / Actionable / Updatable / Least but sufficient
```

同时，围绕 `SKILL-hard` 的讨论又给出两个关键约束：

1. 写给 LLM 的运行时 skill，不能与写给外部系统的治理结构混写。
2. 解释状态难以被低损耗地控制流化。

因此，MALA-Graph 若要成立，它不能被理解为：

- 一个完整解释状态机；
- 一个替代 skill 的运行时正文；
- 一个把全部语义判断离散化的流程表。

它只能被理解为一种**外部治理结构**：  
用于组织局部问题、显式保留缺口与冲突、支持修复动作，并允许诚实停机。

## 2. 本文的理论立场

为了避免再次把猜想写成结论，本文采用三层标记。

### 2.1 `Source`

直接来自给定文档、可以作为起点接受的内容。

### 2.2 `Definition`

为了构造 MALA-Graph 而在本文中引入的形式对象。  
它们是建模选择，不是假装从前文中自动推出。

### 2.3 `Conjecture`

本文认为合理、值得推进，但尚未证明的命题。

后文所有关键点，都按这三层区分。

## 3. `Source`：当前可以直接接受的前提

### 3.1 好问题的基本结构

`Source`

对问题构造而言，以下八要素是核心观察框架：

```text
T = Target
O = Object
U = Unknown
C = Criterion
K = Constraint
A = Action
E = Evidence
B = Boundary
```

三类基本失效是：

```text
Missing / Mixed / Mismatched
```

这三类失效是问题构造任务的最小修复入口。

### 3.2 四个任务判准

`Source`

一个问题是否构造成功，至少要看四个条件：

- `Judgeable`
- `Actionable`
- `Updatable`
- `Least but sufficient`

这四项不是图论对象，而是图要服务的任务准则。

### 3.3 分层约束

`Source`

skill 与控制流属于不同层：

- skill 负责塑造高层语义判断方向；
- 控制流负责外部治理；
- 二者不能在运行时正文中混写。

因此，MALA-Graph 的对象必须是**治理层对象**，而不是“更复杂的 skill 文本”。

### 3.4 解释状态边界

`Source`

并不是所有状态都适合被图化。  
尤其是高语义密度的解释状态，例如：

- 真目标为何如此锚定；
- 某个冲突为何真正阻断回答；
- 某次澄清为何是真收缩而不是措辞改写；

这些内容不能被假定为可被低损耗字段化。

这条边界不是附属提醒，而是 MALA-Graph 的基本理论约束。

## 4. `Definition`：MALA-Graph 的最小对象

### 4.1 历史与材料域

`Definition`

记当前可用材料总体为：

```math
H
```

其中 `H` 可以包含：

- 当前对话历史
- 用户已给材料
- 被允许读取的文档
- 已取得的外部证据

这里的 `H` 不是对象层环境历史，而是**问题构造时可引用的语义材料域**。

### 4.2 局部问题单元

`Definition`

定义一个局部问题单元 `q` 为：

```math
q = (\Sigma, \Pi, \Gamma)
```

其中：

- `\Sigma` 是八要素槽位集合；
- `\Pi` 是当前显式未闭合项；
- `\Gamma` 是当前显式治理标记。

进一步写成：

```math
\Sigma = (T,O,U,C,K,A,E,B)
```

但要强调：  
这里的八要素不是被当作“完整解释状态”，而是被当作**局部问题索引槽位**。

### 4.3 槽位状态

`Definition`

每个槽位 `X \in \Sigma` 采用薄状态表示：

```math
X = (v_X, s_X, w_X)
```

其中：

- `v_X`：当前槽位内容
- `s_X`：槽位状态
- `w_X`：见证或来源指针

槽位状态取值为：

```text
missing | proposed | conflicted
```

这里故意不用更细的控制流枚举。  
原因不是不能再细，而是当前理论上只有这三类是刚需：

- `missing`：该槽位尚未成形
- `proposed`：已有一个当前工作版本
- `conflicted`：存在不可静默抹平的竞争版本

见证 `w_X` 不是长解释文本，而是对 `H` 中依据位置的引用、摘要或索引。  
它的作用是让节点可追踪，而不是替代重新理解。

### 4.4 未闭合项

`Definition`

定义：

```math
\Pi(q)
```

为局部问题单元 `q` 当前仍未闭合的治理缺口集合。  
一个未闭合项可以是：

- 某槽位缺失；
- 某冲突未决；
- 某证据路径未获得；
- 当前边界过宽；
- 当前无法诚实推进。

`\Pi(q)` 的作用不是替代全部诊断，而是给出“为什么还不能结束”的最小外显接口。

### 4.5 治理标记

`Definition`

定义：

```math
\Gamma(q)
```

为局部问题单元的治理标记集合，可包含：

- 当前是否处于可继续修复状态
- 当前是否必须拆分
- 当前是否必须停机
- 当前结果是否只适合交接而不适合直接回答

这类标记是治理信号，不是语义本体。

## 5. 节点的语义地位

### 5.1 节点不是完整解释状态

`Definition`

MALA-Graph 中的节点 `n` 表示一个局部问题单元 `q_n`：

```math
n \leftrightarrow q_n
```

但这个对应不是“节点 = 完整状态压缩”，而是：

> 节点 = 一个局部问题单元的外部治理索引

也就是说，节点只保留足以支持后续治理动作的外显结构，  
不承诺保留全部解释负担。

### 5.2 节点的解释集合

`Definition`

给定材料域 `H`，定义节点 `n` 的解释集合：

```math
\llbracket n \rrbracket_H
```

表示所有与该节点当前槽位、未闭合项和见证一致的“完整问题理解”之集合。

这个定义很重要。  
它明确承认：

- 一个节点通常对应**多种兼容解释**；
- 节点不是无损语义压缩；
- 图操作的目标不是直接得到唯一真解释，而是对解释空间做治理性收缩、拆分或保留。

这一步修复了旧版最大的跳跃：  
不再把节点直接当成严格状态抽象，而是把它当成一个带解释集合的治理索引。

## 6. 图结构

### 6.1 图定义

`Definition`

MALA-Graph 定义为：

```math
G = (N, E, r)
```

其中：

- `N`：节点集合
- `E`：边集合
- `r \in N`：根节点

### 6.2 边类型

`Definition`

边不是逻辑证明边，而是治理关系边。  
当前最小边类型集合可取：

```text
decompose
support
conflict
revise
handoff
```

含义如下：

- `decompose(n_i, n_j)`：`n_j` 是为处理 `n_i` 中某个混杂或过宽部分而创建的子单元
- `support(n_i, n_j)`：`n_j` 为 `n_i` 提供局部支撑
- `conflict(n_i, n_j)`：两个节点承载互不兼容的候选理解或结果
- `revise(n_i, n_j)`：`n_j` 是对 `n_i` 的修订版本
- `handoff(n_i, n_j)`：`n_i` 的结果应进入另一求解阶段

这些边首先服务于组织、追踪和停机，而不是宣称已经刻画了全部语义依赖关系。

## 7. 四个判准在图层的最小对应

### 7.1 可判断

`Definition`

节点 `n` 对应的局部问题单元 `q_n` 是 `Judgeable` 的，当且仅当：

- `C` 不是 `missing`
- 且当前可以判断什么算“答到”或“未答到”

形式上可写为存在局部验证关系：

```math
J_n(y) \in \{valid,\ invalid,\ better,\ worse\}
```

这里不要求数值化，只要求存在可操作的局部判定关系。

### 7.2 可推进

`Definition`

节点 `n` 是 `Actionable` 的，当且仅当存在至少一个治理动作 `m`，使得：

```math
T_m(G,n) = G'
```

并且该变换会改变至少一项：

- 某个关键槽位状态
- 未闭合项集合
- 冲突显式性
- 下一步允许动作

如果任一动作都不再改变这些对象，则节点不能被视为仍可推进。

### 7.3 可更新

`Definition`

节点 `n` 是 `Updatable` 的，当且仅当存在某类可接受证据 `e`，使得将其并入材料域后：

```math
H' = H \cup \{e\}
```

并引起以下至少一种变化：

- 某槽位从 `missing` 变成 `proposed`
- 某 `conflicted` 被细化或保留为分支
- 某未闭合项被关闭或重分类

换句话说，可更新性不是“世界上总能再说点什么”，而是“存在能改变当前治理状态的证据入口”。

### 7.4 最少但足够

`Definition`

在图层，`Least but sufficient` 不再被理解为对象层最优状态抽象，而被理解为：

> 相对于当前治理任务，节点只保留支持下一步修复、冲突保留、交接或停机所必需的结构。

这一定义是治理层定义，不是控制论定理。

可形式化为一个**薄表示原则**：

若删除节点中的某部分保留信息，会导致下列能力之一丧失，则该信息是必要的：

- 选择下一步修复动作
- 说明为何不能继续推进
- 指明冲突来源
- 支持交接

反之，若某信息既不支持这些能力，又要求长期重复解释，则它不应直接进入节点核心状态。

## 8. 图上的基本修复动作

当前最可靠的动作，不应从任意 solver 列表出发，而应从 `SKILL.md` 的三类修复出发。

### 8.1 `clarify`

`Definition`

`clarify` 的作用是补足关键缺失。  
它适用于：

- 某关键槽位处于 `missing`
- 存在可接受的澄清路径或局部证据路径

其结果是使：

```math
s_X: missing \to proposed
```

或使未闭合项减少。

### 8.2 `split`

`Definition`

`split` 的作用是分离混杂。  
它不要求一开始就得到完美分解，只要求把一个无法稳定承载的节点，拆成若干边界更清楚的子单元：

```math
split(n) \leadsto \{n_1,\dots,n_k\}
```

并加入 `decompose` 边。

`split` 的正确性要求不是“语义真分解”已经被证明，  
而是拆分后每个子节点比原节点更适合单独修复。

### 8.3 `correct`

`Definition`

`correct` 的作用是纠正错配。  
它可以作用于：

- 错误目标锚定
- 错误对象归属
- 错误判准
- 错误证据关联

其关键约束是：  
纠正不能无痕覆盖旧理解，而应通过 `revise` 或冲突保留显式留下修订痕迹。

### 8.4 `record_conflict`

`Definition`

当冲突无法诚实消解时，系统不得静默合并。  
此时允许动作：

```math
record\_conflict(n_i,n_j)
```

其作用是把竞争解释显式留在图上，而不是伪装成单一路径。

### 8.5 `stop`

`Definition`

当继续推进将依赖伪造确定性、越界补足或无价值循环时，允许：

```math
stop(n, reason)
```

这里的 `reason` 是治理终止理由，而不是“图已完成”的强断言。

## 9. 诚实停机

### 9.1 停机类别

`Definition`

当前最小停机类别可取：

```text
resolved
missing_info
unresolved_conflict
overbroad
channel_limited
resource_limited
ill_posed
```

其含义分别是：

- `resolved`：局部问题已足以进入下一阶段
- `missing_info`：关键证据缺失，继续推进将变成编造
- `unresolved_conflict`：关键冲突已显式化，但当前无可靠消解路径
- `overbroad`：当前节点仍过宽，必须先拆分或收窄
- `channel_limited`：当前通道不适合继续承载该步求解
- `resource_limited`：预算不足以继续做有意义推进
- `ill_posed`：当前输入尚未形成一个可回答问题

### 9.2 诚实停机判据

`Definition`

节点 `n` 可以诚实停机，当且仅当满足以下两点：

1. 当前不能再给出一个明显改善治理状态的低风险动作；
2. 停止理由可以被明确归类到上述某一类，而不是被伪装成“已经解决”。

这一定义比旧版的“饱满”更弱，但更可靠。  
它先保证不造假，再谈更强的终止理论。

## 10. 本文的正面理论主张

在上述定义之上，本文只主张三件事。

### 10.1 主张一：MALA-Graph 的节点应被理解为治理索引，而不是完整状态

`Conjecture`

如果节点被设计为带见证的局部问题索引，而不是完整解释压缩，那么图结构有可能在不替代语义理解的前提下，帮助组织问题构造过程。

### 10.2 主张二：图操作应被理解为对解释集合的治理

`Conjecture`

与其把图操作理解为“状态方程更新”，不如把它理解为对解释集合

```math
\llbracket n \rrbracket_H
```

的以下治理动作：

- 收缩
- 拆分
- 修订
- 冲突并存
- 停止

这比把节点直接等同于精确状态抽象更符合当前任务。

### 10.3 主张三：诚实停机先于最优停机

`Conjecture`

在问题构造任务里，先建立诚实停机，比先定义全局最优价值函数更基础。  
否则形式化会优先制造“继续推进的幻觉”，而不是约束伪确定性。

## 11. 理论边界

为了避免旧版再犯的错误，这里明确写出本文**没有**证明什么。

### 11.1 本文没有证明节点表示充分

八要素被本文用作节点槽位，是一个有根据的建模选择；  
但本文没有证明它们已经足够，也没有证明它们是最小集合。

### 11.2 本文没有证明固定动作集完备

本文只给出最小修复动作族：

- `clarify`
- `split`
- `correct`
- `record_conflict`
- `stop`

它们是否足以覆盖全部问题构造任务，仍待研究。

### 11.3 本文没有证明图优于直接对话

本文只说明了图若要成立应当如何被理解。  
它并没有证明图路线在工程上一定优于直接长对话。

### 11.4 本文没有恢复旧版的强价值函数

本文刻意不重新引入：

- `Q(G)`
- `VOC`
- 强意义上的 `saturate`

原因不是它们永远不需要，而是：  
在节点语义、动作收益和停止边界尚未站稳之前，这些对象过早。

## 12. 待证明命题

如果后续继续推进，真正值得证明的是下列命题。

### 命题 1：薄节点的治理充分性

`Conjecture`

存在一种薄节点表示，使得系统在多数常见问题构造任务上，不必反复重读全部历史，就能完成：

- 下一步动作选择
- 冲突保留
- 停机归因
- 交接

而又不把复杂度改写成另一份更难解释的长文本。

### 命题 2：修复动作的局部正确性

`Conjecture`

`clarify / split / correct / record_conflict / stop` 可以被赋予局部正确性条件，使其至少不破坏以下原则：

- 不静默抹平冲突
- 不伪造确定性
- 不无痕覆盖错误版本

### 命题 3：解释集合的单调治理性

`Conjecture`

图上的修复动作可以被定义得使解释集合的变化具有可描述的方向性，例如：

- `clarify` 倾向于收缩兼容解释集
- `split` 倾向于把一个混杂解释集拆成多个更局部的子集
- `record_conflict` 倾向于显式保留分支，而不是伪合并

### 命题 4：诚实停机的稳定性

`Conjecture`

对于一类常见任务，停机类别可以具有跨轮稳定性，即：

- 相同材料下不会反复在“已解决”和“无法继续”之间无根据摆动
- 新证据进入时，停机类别的改变是可解释的

### 命题 5：图路线的任务适用域

`Conjecture`

MALA-Graph 不会对所有任务都更优，但可能对以下任务更有价值：

- 缺失、混杂、错配明显
- 需要显式保留冲突
- 需要交接或审计
- 需要诚实停机而不是强行回答

它的适用域需要被经验研究，而不是被先验宣称。

## 13. 当前结论

重写之后，MALA-Graph 的理论基础可以更准确地表述为：

```text
MALA-core 提供：
  好问题的八要素
  好问题的四判准
  三类基本失效

控制流讨论提供：
  分层约束
  解释状态难以强控制流化的边界

本文提供：
  一个更薄的图层建模方式
  局部问题单元、节点解释集合、治理边类型、修复动作、诚实停机
  以及清楚标出的待证明命题
```

因此，当前最合理的结论不是：

> MALA-Graph 已经被证明可行

而是：

> MALA-Graph 可以被正面地重写为一种“外部治理图”理论草案：  
> 节点不是完整解释状态，而是带见证的局部问题索引；  
> 图操作不是全能求解器，而是对解释集合的治理动作；  
> 停止不是最优饱满，而首先是诚实停机。

这比旧版弱一些，但它是一个真正可继续推进的形式化版本。  
它没有放弃理论化，只是把理论对象放回了正确的强度。
