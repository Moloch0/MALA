# 四种认识状态与问题范式

前面的主文已经建立了一个基本判断：回答是在既定问题空间中给出结果，而提问是在构造问题本身的可求解结构。

这个判断还可以进一步压缩成一个更适合日常辨析的框架：当人面对一件事情时，至少可能处在四种不同的认识状态里。只要这四种状态没有分清，“从回答出发”和“从问题出发”就很容易被混为一谈。

## 四种认识状态

对于同一件事情，人至少可能处在下面四种状态中：

1. `知道自己知道什么`
2. `不知道自己知道什么`
3. `知道自己不知道什么`
4. `不知道自己不知道什么`

这四种状态不是心理学趣味分类，而是一个认识论上的判断工具。它们帮助我们区分：当前更需要的是补一个答案，还是先重写问题。

## 一、知道自己知道什么

这是最稳定的一格。主体不仅拥有某些知识，而且知道自己拥有它们。

一个熟练工人知道自己如何判断材料是否合格；一个研究者知道自己已经掌握了哪些定义、定理或实验结果；一个人也可能清楚知道，自己真正要的是稳定，而不是名义上的上升空间。

这一格里，问题通常已经比较成形。主要任务不是再去构造问题，而是在既定结构内调用、组织或陈述已有知识。

所以，如果一个任务主要落在这一格，那么“从回答出发”通常没有问题。这里需要的是表达、检索、推理或说明，而不是重新立题。

## 二、不知道自己知道什么

这一格更容易被忽略。主体其实已经拥有一些可用知识、经验、判准或直觉，但这些内容还没有被显化，因此无法稳定地进入判断。

比如一个人说：“我想换工作，但总下不了决心。”他也许其实已经知道很多东西：什么样的组织结构会让自己迅速消耗，什么样的节奏无法长期承受，什么样的成长机会只是名义补偿。这些知识并不缺，只是还没有被组织成可说、可检验、可比较的结构。

这里真正缺的不是一个外加答案，而是把隐性的已知转成显性的结构。

如果在这一格里匆忙从回答出发，系统往往会直接给建议：换、别换、列 pros and cons、多做调研、问问前辈。这些建议未必错，但它们跳过了一个更早的工作：主体自己到底已经知道了什么。

因此，这一格已经开始显出问题范式的优势。它要求的不是更快给答案，而是先把已知整理出来。

## 三、知道自己不知道什么

这是最像“标准问题”的一格。主体清楚知道缺口在哪里，也知道什么样的信息会填补这个缺口。

“Jeopardy 常规题的作答时间是多少？”

“这个模型在某个 benchmark 上的结果是多少？”

这类问题一旦成立，回答范式就很有效。因为问题空间已经基本给定，任务主要是在其中查找、推理、计算或比较。

所以，如果一个任务稳稳落在这一格，那么“从回答出发”是自然的。它不需要再额外做一层问题构造。

## 四、不知道自己不知道什么

这是最困难、也最根本的一格。主体不仅没有答案，甚至没有正确暴露未知本身。

比如“我为什么总是学不会？”看起来像是在发问，但它可能同时混杂了能力、任务类型、时间分配、反馈质量、目标定义、评价标准等多个层次。这里真正的困难不是缺少一个现成答案，而是连“到底缺了什么”都还没有被切出来。

如果这时直接从回答出发，系统往往会偷偷替主体决定问题到底是什么：它可能把问题理解成意志力不足，也可能理解成方法错误，或者理解成任务选择不当。回答看起来很流畅，但流畅不等于它真的击中了问题。

这就是为什么第四格是问题构造最必要的区域。这里需要的首先不是答案，而是把未知从混乱里第一次暴露出来。

## 为什么回答范式不能覆盖全部情况

现在可以更清楚地看见：从回答出发，并不是错，而是有前提。

这个前提是：问题空间已经给定。也就是说，我们已经知道：

- 问的到底是什么；
- 真正缺的是什么；
- 什么算回答到了；
- 哪些条件 relevant；
- 边界切在哪里。

一旦这些东西已经成立，回答范式当然有效。但问题在于，这种成立并不是总能自动得到的。

回答范式在第一种和第三种状态里通常是充分的：

- 第一种状态里，知识已经拥有，只需调取或表述；
- 第三种状态里，未知已经暴露，只需填补。

但一旦进入第二种和第四种状态，回答范式就会开始失真：

- 在第二种状态里，它会错过主体已经拥有但尚未显化的知识；
- 在第四种状态里，它会替主体预先决定目标、判准和边界。

于是，一个看起来顺滑的回答，常常只是对一个未声明问题的回答。

## 为什么问题范式覆盖更广

从问题出发，并不是简单地“先问再答”，而是承认一个事实：很多时候，真正需要先被处理的不是答案，而是问题本身的成立条件。

它至少要做几件事：

- 判断当前处在什么认识状态；
- 暴露真正的未知，而不是沿用表面问句；
- 把隐性已知、混杂目标、错误判准和缺失约束重新组织起来；
- 把一个话题、愿望或困惑，压缩成一个可判断、可推进、可更新的问题。

因此，问题范式覆盖得更广，不是因为它在每个局部任务上都更强，而是因为它还能处理回答范式处理不了的状态，尤其是第二种和第四种。

更准确地说：

- 回答范式处理的是 `问题已经成立之后怎么办`
- 问题范式处理的是 `问题是否已经成立，以及如何成立`

前者是空间内求解，后者是空间构造。前者在局部上往往更高效，后者在覆盖面上则更全面。

## 这并不意味着任何时候都该先改问题

这里也必须加一个限制。

“从问题出发更全面”并不等于“任何时候都应该先做问题构造”。如果一个请求已经清楚落在第一种或第三种状态，继续强行改写问题，反而会让工作变慢，甚至把原本明确的任务搅浑。

所以，更严谨的说法不是“问题永远高于回答”，而是：

> 当问题空间已经成立时，回答是合适的；当问题空间尚未成立，或者我们不确定它是否成立时，问题构造才是更基础的工作。

这也是为什么一个好的系统不应该执着于某一种固定姿态。它既要能回答已经成形的问题，也要能识别哪些输入其实还没有形成问题。

## 这一附文的落点

如果把这四种状态放回整组文稿里，它真正帮助我们看清的是：为什么“以问题为中心”不是一种修辞偏好，而是一种覆盖范围更大的认识策略。

它不是为了否定回答，而是为了限制回答的适用边界。它提醒我们，很多失败不是因为答案不够多，而是因为问题还没有被写对。

也正是在这个意义上，问题构造才会成为后续讨论的中心：一个好问题由什么构成，它会怎样失效，又该如何被修复。只有这些工作先完成，回答才第一次真正有意义。
