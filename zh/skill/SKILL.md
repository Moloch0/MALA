# 问题构造

## 定义

好问题是在给定目标下，用最少但足够的结构，把真正未知暴露成一个可判断、可推进、可更新的缺口。

这一定义有四个条件：

- `可判断`：什么算回答到了，什么算没有回答到，必须明确。
- `可推进`：不同回答会导向不同的下一步，否则它只是话题。
- `可更新`：新证据进入后，问题和答案都能被修正。
- `最少但足够`：相对于给定目标，既不保留无关冗余，也不删掉关键结构。

这个 skill 的任务只有一个：把原始输入修复到满足这四个条件。

## 元素

一个问题由以下元素构成：

- `目标`：这个问题最终服务于什么。
- `对象`：这个问题作用于什么对象、系统、过程、理论或情境。
- `未知`：真正缺失的是什么。
- `判准`：什么算回答到了，什么算更好或更差。
- `约束`：时间、资源、风险、可观测性、适用范围等限制。
- `动作`：允许通过什么方式推进，例如比较、检验、推理、实验、设计、决策。
- `证据`：什么信息会改变当前判断。
- `边界`：哪些内容属于这个问题，哪些内容不属于这个问题。

如果这些元素没有形成结构，输入就还不是一个好问题。

## 失效形式

坏问题相对于好问题，只有三种基本失效形式：

- `缺失`：某个必要元素没有给出。
- `混杂`：多个元素或多个问题被揉在一起。
- `错配`：元素给了，但给错了，例如把代理指标当目标，把态度当判准，把相关性当证据。

诊断时，不要先发明分类；先检查这三种失效。

所谓冗余，不是第四种失效。它要么来自边界未切清造成的混杂，要么来自把无关内容错误保留造成的错配。

## 工作流程

### 1. 抽取元素

先从原始输入中抽取：

- 目标
- 对象
- 未知
- 判准
- 约束
- 动作
- 证据
- 边界

如果某项没有给出，就明确记为缺失，不要自行偷补。

### 2. 诊断失效

对每个元素检查三件事：

- 是否缺失
- 是否与别的元素混杂
- 是否发生错配

诊断的结果应当落到元素上，而不是落到空泛评价上。

### 3. 执行修复

修复只做下面三类动作：

- 对缺失元素，补足它。
- 对混杂元素，拆开它。
- 对错配元素，纠正它。

常见修复包括：

- 明确真正目标，而不是沿用方便度量的代理指标。
- 把话题压成真正未知，而不是保留宽泛愿望。
- 明确判准，而不是停留在态度表达。
- 加入必要约束，使回答能够改变下一步。
- 指出允许的推进动作，而不是只留下空谈空间。
- 指出哪些证据会更新判断。
- 划清边界，把混在一起的多个问题拆开。

修复的目标不是把话说得更漂亮，而是把结构补完整。

### 4. 验证结果

修复后，只检查四件事：

1. 现在是否 `可判断`
2. 现在是否 `可推进`
3. 现在是否 `可更新`
4. 现在是否 `最少但足够`

如果四项中仍有一项不成立，说明修复还没有完成。

## 输出

默认按下面顺序输出：

```markdown
原始输入的问题
- 缺了什么
- 混了什么
- 错了什么

修复后的问题
> ...

修复说明
- 补了什么
- 拆了什么
- 改正了什么
```

如果原始输入尚未形成问题，就先明确指出：它现在只是话题、愿望、态度或未成形的目标，而不是一个可直接回答的问题。
